# 設計總綱

**狀態：草稿（2026-10-04），站主尚未確認。** 標 ⚠ 的是主 session 依現有文件推論、或文件之間不一致的地方，需要站主決定。

這份只寫最上層的定位與原則，細節一律指向負責的文件，不在這裡重寫，以免兩邊不一致。各面向的規則有變動時，改的是那份文件，不是這份；只有定位或原則改變時才改這份。

---

## 一、網站是什麼

- **IN / ARCHIVE**（`jerrylib.com`）：把自己寫過的文章、用過的技術、做過的專案編成一份可以查詢的目錄。首頁的說法是「私人藏書，公開目錄」。
- 資料結構借用 Linked Data 三元組：三大類（文件、技術、實作）用階層分類號整理，彼此之間用雙向關係連起來，組成一張知識圖譜。
- 後端 `my-dev-grid`（Laravel）提供資料，這個 repo 是公開網站，也是站主自己的管理介面。

⚠ **定位要確認**：`visual-design-language` 開頭寫「這個專案不是作品集，而是知識管理的外接大腦」；但它也是求職作品，站主 2026-10-04 也認為開發者網站應該有個人風格。兩種定位會導向不同的設計取捨：知識庫重查詢效率，作品集重第一印象與辨識度。要決定的是：兩者都是嗎？哪個優先？

## 二、給誰看

1. **非技術背景的訪客**：要能看懂這個網站在做什麼。
2. **工程師、招募方**：找能力的證據，時間很短。
3. **初階開發者**：參考做法。
4. **圖書資訊背景的讀者**：看得懂分類與關係的設計。
5. **站主本人**：用後台管理資料。

前四種是 `mockup-fidelity:ux-review` 模擬的讀者（見 `copy-language`）。用字要讓四種讀者都不需要額外解釋就看得懂。

## 三、個性

- **目錄、圖書館、檔案室**：藏青、黃銅、卡紙底色、襯線標題、目錄卡材質（About E 版，D-59、D-60）。
- **第一人稱、平實**：說有什麼就說什麼，不用行銷語氣（`copy-language`）。
- ⚠ **個人風格的強度**：研究中（front milestone 2）。站主的初步想法是用技術的象徵符號或 icon。要跟目錄、圖書館的個性怎麼結合，還沒決定。

## 四、核心原則

| #   | 原則                                                                                                               | 依據                                                                                           |
| --- | ------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------- |
| 1   | **每個元素都要表達真實的東西**。看起來有意義、其實沒有意義的元素（假訊號）算 bug，不是風格問題                     | `visual-design-language`（導覽列脈衝圓點的例子）                                               |
| 2   | **文字要跟資料一致**：寫出來的說法，資料要撐得住                                                                   | `copy-language`「Claims must match the data」                                                  |
| 3   | **數值要有來源**：配色由工具產生並驗證對比度；設計值走 token → 元件規則 → 全站架構                                 | `visual-design-language`、D-59                                                                 |
| 4   | **先畫圖、讓讀者審，再實作**：新頁面或版面改動先做 mockup，跑 ux-review，站主選定後才寫程式，寫完做 fidelity-check | `mockup-fidelity`、D-67、D-69                                                                  |
| 5   | **探索型頁面可以有表現力，操作型頁面要安靜**：About、首頁可以有敘事；文章閱讀、後台、編輯頁、圖譜畫布不加裝飾      | D-93                                                                                           |
| 6   | **無障礙是底線**：字級下限、對比度 AA、尊重「減少動態」                                                            | D-68、`base.css`                                                                               |
| 7   | **不為裝飾犧牲速度**：動畫只動 transform 與 opacity，LCP、INP 不能退步                                             | D-93                                                                                           |
| 8   | **避開 AI 設計的常見套路**                                                                                         | `visual-design-language`                                                                       |
| 9   | ⚠ **把隱性的結構變成明確、可用的東西**：這是站主碩論、側專案、現職工作的共同主線，可以當成網站想傳達的核心價值     | `daily-claude-summary/reports/job-search-positioning.md`（推論，站主未確認是否要放進網站設計） |
